# 审查口径与组合页验证要点

> 层级：L3 方法（冲突顺序见 [SKILL.md](../SKILL.md#1-文档分四层按层读取)）。仅在盘点、对比审查或回溯交互失败时使用；普通局部修改直接按 [design-recipes.md](design-recipes.md) 最小验证。

## 五条核心比较口径

比较前必须对齐**角色、操作、状态、主题、UI/Graph 缩放与具体属性**，并至少提供两个具名样本（单项故障提供可复现信号）；动效须对比同阶段进/退过程，单张终帧不构成冲突证据：

1. **单项参考**：说明某控件现行做法，不据单图声明与其他控件冲突。
2. **场景适配**：不同对象、密度、范围、状态或渲染层的合理表达，不要求统一外形或时长。
3. **局部一致性候选**：同角色/同状态/同缩放下仅比单一属性；候选不等于 bug，也不自动授权修改。
4. **行为差异**：同类输入与同手势产生不同结果；未定义产品期望前不直接定性为故障。
5. **功能冲突 / 故障**：可复现的矛盾结果、状态遮蔽、错发命令或不可达；不得以色板、CSS 写法或时长不同冒充故障。

每项登记结构：`id → 两具名对象/单项故障 → 对齐条件 → 属性与证据 → 分类（功能适配/可选一致性/规范覆盖遗漏/已复现故障/待证）→ 关联 CU 规则`。历史记录仅对当时 source hash 有效，源码漂移后先重采再判定。

## 组合页与模拟回包防伪要点

- **绑定真实发布者与消费入口**：区分完整 snapshot、字段增量与专用 reply，分别核对 chrome 与 surface 字段合同（勿先写全模型提前覆盖 binding 掩盖取消逻辑）。
- **深拷贝快照防活动别名**：传入 UI 前深拷贝输入与逐帧记录，防止 UI 反写数组污染“初态”证据。
- **区分显示与已提交状态**：自建异步模拟服务须在提交前按真实 owner 合同校验身份、版本与退役态（测 A 退役 → B 成功 → A 迟到），纯记录 bridge 须标明后端未测。
- **真实手势起点与字体加载**：记录真实 pointer/key target、`activeElement`、capture 与坐标，禁 forced click 或伪造事件；字体与长内容须在 `fonts.ready` 后核对真实加载 face 与最终 DOM 可达路径。
- **分层报告与锚点校验**：同一文件可能并存 legacy 与现行模块，用公开 namespace + 真实调用链绑定私有 helper（不盲信旧行号）；按组件、组合 WebKit、嵌入 WKWebView、native、DAW、音频分层列明已测与未测。
