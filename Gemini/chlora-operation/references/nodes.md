# Graph nodes, containers and routing

Choose an entity by the requested signal path. The Graph surface provides **Snake (`bundle`), Merge (`sum`), Fanout (`fanout`), Router / Matrix (`router`), Align (`channel`), Stack (`stack`), Pin (`pin`), LFO (`lfo`), IR Loader (`add_ir`), Jelly / Nebula (`nebula`), Spectrogram (`spectrogram`), LFE Spectrum (`lfespectrum`), and Level Meter (`levelmeter`)**, plus **Groups**, **Comments**, **Port Snakes**, **Graph IN/OUT**, and **hosted plug-in nodes**; Standalone FileGraph adds **File Source**, **Device Input / Device Output**, **Monitor Bus / Playback**, and **Chloe Input**. A container, wrapper or parameter link does not establish a parallel audio route. Read [graph-recipes.md](graph-recipes.md) for composed operations, [controls-and-plugins.md](controls-and-plugins.md) for gains, flags and hosted parameters, and [layout.md](layout.md) for geometry, pins, wire styles and camera. Discover exact current schemas (`clara schema <id>` / `chlora_describe_tool`) rather than deriving arguments from this table.

Derive every span/partition from current input/output widths, port roles and processor support. Counts may differ between IN and OUT and may be mono, stereo, odd or mixed; a named immersive layout is not required. Stack creation uses uniform width 1 or 2; stereo-row splitting can produce mixed lane widths. Native limits below are capability bounds, not fixed session sizes or routing recipes.

## Standalone FileGraph, Device I/O, Monitor Bus & DarkRoom Repair

Standalone FileGraph operates with `instanceId: 0` (never claims Chloe) and uses `bindingGeneration` + `sourceGraphLifetime` (plus `expectedSourceGeneration` for scoped source operations):

- **File Graph workspace, File Source, Chloe Input, App Input & Device I/O (`chlora_file_graph`, `chlora_file_graph_project`)**:
  - Project lifecycle, Playback Volume Automation & patchbay inputs (`chlora_file_graph_project`): `action="new" | "open" | "select" | "rename" | "close"` (`open` takes `bindingGeneration` + absolute `.filegraph` `path`, auto-detaches Patchbay, normalizes via `realpath`, and opens directly without a chooser), `loadSource` (scoped calls require `nodeKey` + `sourceGraphLifetime` + `expectedSourceGeneration` together, resolving by `nodeKey` when `index` is omitted; or legacy), `cancelSource`, `selectAudition`, `playSelection`, `connectOutput`, **`setSourceAutomation`**, **`clearSourceAutomationPreview`**, **`setNodePlaybackAutomation`**, **`clearNodePlaybackAutomationPreview`**, **`addChloeInput`**, **`chloeRefresh`**, **`chloeSetNode`**, **`addAppInput`**, **`deviceRefresh`**, **`deviceConfigure`**, **`deviceSetNode`**.
    - `addChloeInput` and `addAppInput` require **`sourceGraphLifetime`** (from `state.fileGraph.sourceGraphLifetime`) and coordinates **`x`**, **`y`** (plus optional `channels` 1..128, `groupId`). `addAppInput` also accepts optional `deviceId` to create and bind a target Mac app in one step; `addChloeInput` accepts optional `chloeInput` object + `adoptChannels` (`bool`) for one-step creation & configuration.
    - `chloeSetNode` requires `bindingGeneration`, `sourceGraphLifetime`, `nodeKey`, and **`chloeInput: {"instanceId": <int>}`** (not top-level `instanceId`; pass `{"instanceId": 0}` to disconnect), e.g.:
      `{"bindingGeneration": 1, "action": "chloeSetNode", "sourceGraphLifetime": "3", "nodeKey": "14", "chloeInput": {"instanceId": 0}}`
      The `chloeInput` schema supports `instanceId` (`0..64`), `trackName`, `dawName`, `channels`, `mapping`, `gainDb`, `muted`, `mutes`, `solos`, `meterMode`, `meterStyle`, `formatPreference`.
    - `deviceRefresh` (needs only `bindingGeneration`): refreshes `state.fileGraph.deviceIo.inputDevices` (entries with `type == "Application Audio"` list capturable running Mac apps with `id` e.g. `"application\ncom.apple.Music"`, `name`, `channels`, `hasAudioProcess`) and `outputDevices`.
    - `deviceConfigure` (`bindingGeneration`, `sourceGraphLifetime`): per-node binding via `nodeKey` + `deviceId` (bind `App Input` to `"application\ncom.apple.Music"` or `Device Input`/`Output` to hardware ID; `""` disconnects), or global defaults via `inputId` + `outputId`.
    - `deviceSetNode` (`bindingGeneration`, `sourceGraphLifetime`, `nodeKey`, `deviceIo`): updates `channels` (`1..128`), `mapping` (`[-1..127]`, `-1`=Off), `gainDb` (`-100..12`), `muted` (`bool`), `mutes` (`bool[]`), `solos` (`bool[]`), `meterMode` (`"peak"|"rms"`), `meterStyle` (`"bars"|"spatial"`), `formatPreference` (`0..2147483647`), `deviceId` (`string`). **Partial patches are supported**: `MainComponent.h` merges `deviceIo` with the node's current `node.deviceIo` (e.g. `{"gainDb": -4.5}` or `{"mutes": [true, false], "meterMode": "rms"}`), as well as complete objects; if `channels` is changed alongside explicit `mapping`/`mutes`/`solos` arrays, each supplied array's length must match the new `channels`.
  - Sources & transport (`chlora_file_graph`): `command="show" | "new" | "open" | "save" | "load" | "devices" | "addOutput" | "outputPath" | "render" | "play" | "stop" | "seek" | "monitor" | "export" | "cancel" | "close" | "undo" | "redo" | "addSource" | "setSourceControl" | "sourcePlayback"` (`addSource`, `addDeviceInput`, `addDeviceOutput`, and `addOutput` return `mcpResult: {nodeKey, changed: true}`).
  - `sourcePlayback` supports `action: "seek" | "play" | "stop" | "toggle" | "loop" | "clearLoop"` on positive sources or legacy IN (`index: -2`, never `-1`). Loop edits create FileGraph undo steps (`chlora_file_graph` `undo`/`redo`); transport actions do not.

  - `addDeviceInput`, `addDeviceOutput`, `deviceRefresh`, `deviceConfigure(inputId, outputId, ...)` (when `deviceId` is passed, also requires `nodeKey` and `index: 0..2147483647`), `deviceStart`, `deviceStop`, `deviceSetNode(...)` (now also accepts `deviceId`, `meterMode`, `meterStyle`, `formatPreference` `0..2147483647`, matching `chlora_file_graph_project`; `setSourceControl` `gainDb` variant also accepts optional `commit: bool`). ## Group and Stack rules

- To wrap only existing Groups, pass `nodeKeys: []` and nonempty `childGroupIds`.
- Read attached Fanout positions from resolved renderer geometry (`chlora_graph_get_layout_geometry`), not raw node `x`/`y`. Ungrouping a framed container releases adopted Fanouts beside its boundary (output left, input right).
- After Group creation or Undo/Redo changing boundaries, read back every Group's input/output ownership and crossing MAIN/SIDECHAIN wire identity/order. Connected SIDECHAIN crossings use separate input carriers; an intentionally authored bypass skipping a parent Group must be preserved on restore.
- Selecting only Router, Align (`channel`), or LFO nodes (with at least one Router/Align having real MAIN I/O) creates independent input/output boundary-carrier pairs per Router/Align; LFO creates zero audio ports.
- `connect_group_fanout` is full-width MAIN without offsets; `connect_bus` supports bounded ranges between a regular Group boundary with nonzero local width and an ordinary unwrapped non-Sum peer (`source MAIN -> destination MAIN|SIDECHAIN`).

Table tool names without prefix mean `chlora_graph_...`.

## Distinguish routing and control propagation

- **Parallel audio** requires explicit distribution (`Fanout`) and recombination (`Merge`) edges. Stack lanes partition a channel span; Group adds ownership and boundaries, not parallel summing.
- **Multi Channel Strip** and **Multi Mono Strip** are session modes (`chlora_set_mode`), not Graph nodes.
- **Stack macro** (`set_stack_macro`) drives compatible lane parameters from the first member; **Multi Link** (`set_multi_link`) links compatible ordinary nodes persistently; **sync selection** (`set_sync_selection`) is transient parameter selection.
- **Stack Names** (`chlora_graph_set_stack_names`) is a visible WebUI preference taking `on: bool` and strictly one of `groupId` (`1..2147483647`) or `nodeKey` (canonical uint32 string, mutually exclusive XOR); poll the async operation and read `get_view_preferences.stacks[].namesAvailable/namesOn`.

## Exact wires and safe edits

- Read visible wires and stable keys from `chlora_graph_get_summary` or `chlora_get_state`.
- `connect_channel` connects one channel (`destinationRole?: "main" | "sidechain"`, default `"main"`, where sidechain exempts the MAIN-only Snake guard); `connect_bus` maps a contiguous MAIN span to MAIN or SIDECHAIN. Connections are additive unless `replaceExisting: true`. Note: unwrapped (`snakeWrapped: false`) **`Router`** or **`Merge (Sum)`** nodes do not support explicit ranges via `chlora_graph_connect_bus` (fails with `"Graph bus endpoints do not support an explicit range"`); use per-channel `chlora_graph_connect_channel`, or wrap/use branches with `chlora_graph_connect_snake`.
- `disconnect_channel` (also accepts `destinationRole?: "main" | "sidechain"`) cannot remove part of an aggregate cable; use `disconnect_snake`. SIDECHAIN wires can also be disconnected via `delete_selection` with exact `fromRole`/`toRole`/`fromCh`/`toCh`.
- `chlora_graph_insert_builtin_on_wire` atomically inserts `bundle`, `merge`, `fanout`, or `router` (with optional `routerMatrix: bool`, default `false`) on an exact visible MAIN wire; `chlora_graph_splice_existing_builtin` inserts a detached existing one while retaining its identity/state.
